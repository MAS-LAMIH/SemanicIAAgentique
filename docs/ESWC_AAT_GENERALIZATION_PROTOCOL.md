# AAT newly described artifact protocol — proposed, not executed

Question: can the unchanged finite semantic controller select and safely execute
Usages for a newly described artifact, using observed context and reviewed meaning,
rather than a harness-selected action? This is a small prospective case study, not
a statistically generalizable sample or a claim of automatic behavioral discovery.
The acquisition pipeline is currently design only; no new provider is integrated.

## Feasibility and honest boundary

The present `room-step/1` profile fixes the Thing IRI, /state observation, /heat and
/cool POST paths, RevisionRequest/RoomReply schemas, Celsius integers18–26, atomic
expected_revision, readiness flags and frame/counter observations. The runtime
cannot admit arbitrary independent APIs just by adding RDF. A new room instance
using the same author's fixture can test description/order invariance, but **cannot**
establish external generalization. The focused audit tests are that internal control.

No compatible independently developed API is established by this task. The already
preserved Radicale feasibility study (`docs/V4_HELD_OUT_GENERALIZATION_RESULTS.md`)
concerns CalDAV, not heating/cooling; it supplies no compatible AAT candidate. No
Provider C search or broad new provider search was performed. External-API execution
is blocked pending a genuinely compatible reproducible candidate, not silently
replaced with a same-author emulator. Do not infer a candidate's compatibility from
an operation name or implement a proxy to make the profile fit.

If a known candidate is nominated later, inspect only that candidate after approval:
require independently developed provenance, pinned release/dependencies, local
resettable native state, public API documentation and independent native inspection.
Check the exact existing profile/bindings before writing semantic descriptions. If
incompatible, retain a negative result and stop. Any new observer/binding/profile
code is a separate extension study, not zero-change generalization under this one.

## Lock before exposure

Record commit and SHA-256 for `experiments/aat/{model,rdf,runtime}.py`, ontology,
original room graph and baseline review. Archive environment/dependencies and the
curator's reference/expected native transitions **before** acquisition/integration.
Freeze ScriptedReasoner decision policy, six-turn budget and single dispatch limit.
Use fresh output directories and never overwrite `eswc_aat/run-001` or audit logs.
All changes, including provider-specific code and failed attempts, must be enumerated
against that baseline. A controller/policy/profile change fails the zero-change claim.

An evaluator curator works from native API/specification and independently written
state checks, not generated RDF effects or runtime predictions. An acquisition
contributor receives public documentation and baseline profile, not private answers.
An auditor checks source hashes and results. Separate files/process imports alone
are not blinding: use distinct restricted workspaces/operators if asserting isolation.
If roles overlap, disclose exposure and characterize native checks as separate code
paths, not independent authorship. Lock expectations even when blinding is impossible.

## Small gate and comparison

For an eligible artifact, lock concrete initial states and native expected transitions
before generating Usages. Minimum task families:

| Family | Expected selection/outcome, independent of opaque identifiers |
| --- | --- |
| Below target, upward effect applicable | Choose the eligible goal-establishing operation; one correct native transition |
| Above target, downward effect applicable | Choose opposite effect; one correct native transition |
| Target already holds | Verify, no mutation |
| Neither applicable | Abstain, no mutation |
| Relevant readiness/effect unknown | Quarantine or abstain; never invent applicability |
| Context changes after proposal | Guard rejects stale intent, fresh observation, reconsider using actual state |
| Revision conflict / uncertain timeout | Safe stop; no speculative retry; retain late native state |
| HTTP success with wrong effect/frame | Detect failure; no accepted success |

Do not fabricate external fault support. Where deterministic injection/reset/native
inspection is unavailable, mark the family unsupported and report reduced coverage.
Faults from an instrumented service must be distinguished from unmodified native
behavior. Preserve unrelated records and externally authorized interventions separately.

Use the same semantic controller before/after new descriptions. Include a fair
procedural-knowledge arm encoding independently documented native facts, sharing
observations, goals, budgets and verification. Disclose the shared controller and
candidate evaluator: this is a knowledge-representation comparison, not independent
agents. Identifier/order permutations are internal invariance controls. Report
physical operations and native effects, not identical opaque handles as the metric.

## Measurements and decision rule

- Structural extraction: assertion precision/recall, supported subset coverage,
  unsupported features and provenance coverage against the locked reference.
- Behavioral acquisition: pre-review and post-review correctness/completeness of
  every precondition/effect/frame/grounding/observation; unknowns and human edits.
- Admission: admitted/quarantined/rejected counts and exact reasons; wrong reviewed
  semantics that pass structure count as semantic errors, not successful acquisition.
- Selection: eligible goal-contributing physical action, stale-intent rejection,
  reconsideration, safe abstention and unnecessary/unauthorized dispatches.
- Execution: native goal, exact transition, counters, frame and usable response;
  success only after verified state. Timeouts/unknown outcomes are never successes.
- Changes: provider RDF assertions, manual corrections, observer/binding/evaluator/
  procedural-adapter code separately; runtime/policy/vocabulary hashes must match.
- Record observed wall time/tool execution and failures/rework; unmeasured effort is
  null. Static size is not engineering time. Repeated runs are not independent APIs.

Successful supported-profile generalization requires correct complete reviewed
Usages, admission, correct native outcomes and no frozen controller/runtime/profile
changes. Report automated extraction success separately from reviewed behavioral
completion; neither implies the other. Unknown semantics safely blocked is a safety
result, not completed goal achievement. Preserve every failure and partial result.

## Smallest execution sequence and approval gates

1. Investigator approves scope, exact compatible candidate (currently pending),
   curation roles and any exposure limitations; no new broad search is implied.
2. Curator pins native environment, locks reference and concrete native-state gate.
3. Contributor implements only the bounded structural extractor described in
   `ESWC_AAT_AUTOMATIC_ACQUISITION_DESIGN.md`; save unreviewed graph/provenance.
4. Measure against locked reference, review behavioral gaps and record every edit;
   reject unsupported profile, then explicitly admit the reviewed hash if complete.
5. Execute locked cases with isolated resets and deterministic interventions where
   available; retain observations, proposals, feedback, guards, HTTP/native journals.
6. Seal raw JSON/RDF/source hashes; derive CSV/Markdown summaries separately; verify
   source stability and all native expectations. Report blocked coverage and changes.
